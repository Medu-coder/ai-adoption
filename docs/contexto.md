# Contexto y enfoque inicial

## Problema
Prototipar desde un Mac propio no sirve si luego hay que "exportar" el entorno a cada persona.

## Solución: empaquetar conocimiento, no entornos

| Se empaqueta y comparte | Lo configura cada persona |
|---|---|
| Skills (instrucciones + scripts para una tarea) | Conectores y sus inicios de sesión |
| Plugins (conjunto de skills) | Memoria y preferencias |
| Instrucciones y documentos base de un Proyecto | Carpetas locales y app de escritorio |
| Artefactos/plantillas (compartidos por enlace) | Su plan de Claude |

## Vías de distribución
- **Personas sueltas (Pro/Max):** este repo con un plugin por perfil; se instala desde Claude o se pasan skills en .zip. Las mejoras llegan actualizando el repo.
- **Equipos/empresas (Team/Enterprise):** el administrador distribuye skills y plugins a la organización y crea Proyectos compartidos.

## Método propuesto
1. Entrevista corta: 2–3 tareas repetitivas reales de la persona.
2. Prototipo con datos ficticios.
3. Empaquetado como skill o plugin en este repo.
4. Sesión de 30–45 min en su equipo: instalar, conectar sus apps, ejecutar con sus datos.
5. Revisión a las dos semanas.

El cuello de botella suele ser el paso 4: que la primera ejecución real salga bien. Eso genera adopción.
